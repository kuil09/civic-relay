# SKILL.md Contract

모든 스킬은 독립적으로 읽을 수 있으면서도 오케스트레이터 안에서 같은 파일 계약을 따라야 한다.

## 필수 섹션

1. 목적
2. 실행 조건
3. 입력
4. 절차
5. 자료 우선순위 또는 판단 규칙
6. 출력
7. `case.json` 변경 범위
8. 자체 검증
9. 실패·불확실성 처리
10. 금지 행동
11. 다음 단계
12. PRD 추적

## 공통 불변조건

- 사용자의 원문을 덮어쓰지 않는다.
- 스킬은 선언한 파일과 필드만 변경한다.
- 조사 실패를 새 사실로 채우지 않는다.
- 승인 레코드는 `approve` 명령과 사람의 명시적 확인만으로 생성한다.
- `mail-dispatch` 외 스킬은 외부 메시지를 보내지 않는다.
- `mail-dispatch`도 유효한 승인과 현재성 게이트 없이 보내지 않는다.
- 외부 사실에는 출처 식별자를 연결한다.
- 다음 단계 조건이 충족되지 않으면 차단 이유와 필요한 작업을 기록한다.

## 스킬 결과 상태

각 실행은 다음 중 하나로 끝난다.

- `complete`: 출력과 자체 검증을 통과함
- `partial`: 일부 결과는 있으나 조사 항목이 남음
- `blocked`: 공식 자료·승인·도구가 없어 다음 단계 불가
- `not_applicable`: 사례에 해당하지 않음

`partial`과 `blocked`는 실패를 숨기는 표현이 아니다. 남은 항목을 구체적으로 기록해야 한다.
