# stakeholder-analysis

## 목적

정책 변화의 수혜·부담·권리·비용·집행 책임을 당사자별로 분리한다.

## 실행 조건

문제 정의와 최소 근거가 있을 때.

## 입력

- 문제 정의
- 관련 통계·당사자 공개 입장
- 법·권한 지도

## 절차

- 직접 수혜자와 직접 부담자를 나눈다.
- 권리 침해 가능 집단과 대표 단체를 식별한다.
- 비용 부담자, 집행자, 시설 운영자를 기록한다.
- 각 집단의 이해와 우려를 당사자 자료에 근거해 작성한다.
- 공개 입장이 없으면 추정하지 않고 미확인으로 둔다.

## 판단 규칙

- `AGENTS.md`의 공식 자료 우선순위와 승인 경계를 따른다.
- 사실과 관찰, 추론, 가치 판단, 제안을 혼합하지 않는다.
- 실행 결과는 `complete`, `partial`, `blocked`, `not_applicable` 중 하나로 기록한다.

## 출력

- `04-stakeholder-map.md`
- `stakeholders`

## `case.json` 변경 범위

- `stakeholders`

선언한 필드 밖의 구조화 상태와 승인 이력은 변경하지 않는다.

## 자체 검증

- 수혜자만 나열하지 않는다.
- 권리 침해 가능 집단이 별도로 보인다.
- 대표성이 불명확한 단체를 전체 당사자 의견으로 일반화하지 않는다.

## 실패·불확실성 처리

- 당사자 자료가 없으면 인터뷰·공개 의견 수렴 과제로 남긴다.

## 금지 행동

- 취약 집단의 필요를 편의상 추정
- 반대 집단을 악의적으로 묘사
- 기관과 개인의 이해를 혼합
- 승인 레코드를 스스로 생성하거나 사람을 대신해 승인하지 않는다.
