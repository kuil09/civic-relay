# issue-intake

## 목적

사용자의 자유로운 문제 제기와 원하는 변화 수준을 원문 그대로 보존하고 사례의 최소 메타데이터로 구조화한다.

## 실행 조건

새 사례를 만들거나 기존 사례의 최초 진술을 명시적으로 교체하는 경우. 원문 교체는 새 버전 또는 새 사례로 처리하고 기존 원문을 덮어쓰지 않는다.

## 입력

- 사용자 자연어 진술
- 선택적 지역·시설·시간 정보
- 원하는 결과 범위

## 절차

- `case_id`와 사례 제목을 정한다.
- 사용자 문장을 `00-intake.md`와 `case.json.original_statement`에 그대로 기록한다.
- 문제, 경험, 선호안, 감정 표현, 원하는 결과를 분리하되 원문을 수정하지 않는다.
- 관할·장소·시간·대상 집단의 명시값과 미상값을 기록한다.
- 부족한 정보는 질문이 아니라 `research_tasks` 성격의 조사 항목으로 남긴다.

## 판단 규칙

- `AGENTS.md`의 공식 자료 우선순위와 승인 경계를 따른다.
- 사실과 관찰, 추론, 가치 판단, 제안을 혼합하지 않는다.
- 실행 결과는 `complete`, `partial`, `blocked`, `not_applicable` 중 하나로 기록한다.

## 출력

- `00-intake.md`
- 초기 `case.json`

## `case.json` 변경 범위

- `case_id`, `title`, `jurisdiction`, `original_statement`, `desired_change`, `status`

선언한 필드 밖의 구조화 상태와 승인 이력은 변경하지 않는다.

## 자체 검증

- 원문이 두 위치에 동일하게 존재한다.
- 문제 현상과 선호 해결안이 분리되어 있다.
- 미확인 원인을 사실로 기록하지 않는다.

## 실패·불확실성 처리

- 관할을 모르면 `null`로 둔다.
- 개인정보가 포함되면 로컬 비공개임을 표시한다.
- 입력 자체가 불명확해도 원문을 보존하고 다음 구조화 단계로 넘긴다.

## 금지 행동

- 원문을 더 공손하거나 정책적인 문체로 대체
- 사용자의 소속·경험·피해를 추정
- 이 단계에서 법률·수신자·정책 결론 확정
- 승인 레코드를 스스로 생성하거나 사람을 대신해 승인하지 않는다.
