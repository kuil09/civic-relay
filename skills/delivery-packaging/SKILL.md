# delivery-packaging

## 목적

동일한 핵심 정책 문서와 수신자별 소관 설명을 결합해 검토 가능한 개별 전달 패키지를 만든다.

## 실행 조건

정책 문서와 수신자 매트릭스가 검토되었을 때.

## 입력

- `07-policy-proposal.md`
- 선택된 recipients
- 배포 범위와 요청 사항

## 절차

- 공통 문서의 버전과 해시를 고정한다.
- 수신자별 제목, 호칭, 소관 이유, 기대 조치만 조정한다.
- 다른 수신자의 주소를 포함하지 않는다.
- 실제 선택된 기관 범주로 배포 고지를 만든다.
- 이메일·공식 폼·우편·전화 스크립트별 패키지를 생성한다.
- `build/review.md`에서 문서·수신자·고지를 함께 검토한다.

## 판단 규칙

- `AGENTS.md`의 공식 자료 우선순위와 승인 경계를 따른다.
- 사실과 관찰, 추론, 가치 판단, 제안을 혼합하지 않는다.
- 실행 결과는 `complete`, `partial`, `blocked`, `not_applicable` 중 하나로 기록한다.

## 출력

- `09-cover-emails/*.md`
- `build/distribution-notice.md`
- `build/outbox/` 초안

## `case.json` 변경 범위

- `artifacts`, 초안 dispatch 레코드

선언한 필드 밖의 구조화 상태와 승인 이력은 변경하지 않는다.

## 자체 검증

- 모든 선택 수신자에 정확히 하나의 커버 문안이 있다.
- 공통 문서 해시가 동일하다.
- 배포 고지와 선택 수신자 조직이 일치한다.
- 주소 상호 노출이 없다.

## 실패·불확실성 처리

- 검증 만료·직책 불일치·커버 누락 시 패키징을 중단한다.
- 메일이 없으면 대체 채널용 문안을 만든다.

## 금지 행동

- 문구 무작위 변형
- 보내지 않은 기관을 전달 대상으로 표시
- 여러 시민이 보낸 것처럼 가장
- 승인 레코드를 스스로 생성하거나 사람을 대신해 승인하지 않는다.
