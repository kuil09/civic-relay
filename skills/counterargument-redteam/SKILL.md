# counterargument-redteam

## 목적

사용자 제안과 각 대안의 가장 강한 반론, 악용 가능성, 집행 실패, 잔여 위험을 드러낸다.

## 실행 조건

이해관계자와 정책 대안이 존재할 때.

## 입력

- `stakeholders`, `options`
- 당사자 공개 입장과 반대 근거

## 절차

- 권리 침해, 예외 확대, 단속 실패, 비용 전가, 행정 부담 관점에서 반론을 만든다.
- 허수아비가 아닌 상대측 최강 논리를 최소 3개 작성한다.
- 각 반론의 사실 근거와 가치 판단을 구분한다.
- 대응 가능한 조건·지표·중단 기준을 설계한다.
- 대응할 수 없는 부분은 잔여 위험으로 남긴다.
- 더 나은 대안이 있으면 최초 안을 폐기 대상으로 표시한다.

## 판단 규칙

- `AGENTS.md`의 공식 자료 우선순위와 승인 경계를 따른다.
- 사실과 관찰, 추론, 가치 판단, 제안을 혼합하지 않는다.
- 실행 결과는 `complete`, `partial`, `blocked`, `not_applicable` 중 하나로 기록한다.

## 출력

- `06-counterarguments.md`
- `counterarguments`

## `case.json` 변경 범위

- `counterarguments`, 필요 시 `options`의 위험·중단 조건

선언한 필드 밖의 구조화 상태와 승인 이력은 변경하지 않는다.

## 자체 검증

- `strength=strong` 반론이 최소 3개다.
- 모든 반론에 대응과 잔여 위험이 있다.
- 제안 지지 논리만 반복하지 않는다.

## 실패·불확실성 처리

- 당사자 관점을 근거 없이 재현할 수 없으면 공개 입장 조사 과제로 남긴다.

## 금지 행동

- 반론을 무지·악의로 치부
- 해결되지 않은 위험 삭제
- 사용자의 선호 때문에 치명적 반론 약화
- 승인 레코드를 스스로 생성하거나 사람을 대신해 승인하지 않는다.
