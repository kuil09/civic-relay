# response-tracking

## 목적

기관·의원실 회신을 원문과 분리된 분류·요약·후속 작업으로 기록하고 다음 제안 버전에 연결한다.

## 실행 조건

발송 기록 또는 수동으로 수신한 공식 답변이 있을 때. 회신이 없어도 상태만 기록할 수 있다.

## 입력

- 회신 원문
- recipient_id와 가능한 dispatch_id
- 사용자 분류 수정

## 절차

- 원문을 `11-responses/`에 보존한다.
- 접수, 소관 아님, 이관, 자료 요청, 반대, 검토 약속, 면담, 불확실로 분류한다.
- 원문과 AI 요약을 분리한다.
- 이관 경로, 추가 자료, 수정 요구, 면담 요청을 작업으로 추출한다.
- 기관별 반응과 제안서 버전 변화를 시간순으로 남긴다.
- 후속 메시지는 별도 초안과 승인으로 보낸다.

## 판단 규칙

- `AGENTS.md`의 공식 자료 우선순위와 승인 경계를 따른다.
- 사실과 관찰, 추론, 가치 판단, 제안을 혼합하지 않는다.
- 실행 결과는 `complete`, `partial`, `blocked`, `not_applicable` 중 하나로 기록한다.

## 출력

- `11-responses/*.md`
- `12-follow-up.md`
- `responses`

## `case.json` 변경 범위

- `responses`, `status=follow_up`, 추가 조사 작업

선언한 필드 밖의 구조화 상태와 승인 이력은 변경하지 않는다.

## 자체 검증

- 원문 파일과 recipient가 연결된다.
- 자동 분류를 사람이 수정할 수 있다.
- `no_response`를 거부로 해석하지 않는다.

## 실패·불확실성 처리

- 발송 ID를 모르면 recipient와 수신 시각으로 기록하고 연결 미확정 표시를 한다.
- 분류가 모호하면 `uncertain`을 사용한다.

## 금지 행동

- 기관 답변의 진정성·정치적 의도 단정
- 회신 반대 내용 삭제
- 사용자 승인 없는 후속 발송
- 승인 레코드를 스스로 생성하거나 사람을 대신해 승인하지 않는다.
