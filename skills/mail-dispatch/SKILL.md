# mail-dispatch

## 목적

승인된 전달 패키지를 개별 초안으로 저장하거나 명시적 외부 어댑터로 발송하고 재현 가능한 명세를 남긴다.

## 실행 조건

초안은 problem~document 승인이 유효할 때. 실제 send는 6단계 승인과 24시간 이내 수신자 검증이 모두 유효할 때.

## 입력

- `09-cover-emails/`
- 정책 패키지 해시
- 선택 recipients
- 승인 기록
- 외부 메일 어댑터

## 절차

- 기본 모드 `draft`에서 수신자별 `.eml` 또는 대체 채널 문서를 만든다.
- `send` 전 모든 승인 해시와 수신자 현재성을 재검증한다.
- 동일 case/document/recipient 성공 키를 검사한다.
- 각 수신자를 별도 메시지로 외부 어댑터에 전달한다.
- 공급자 결과와 실패 사유를 명세에 기록한다.
- 실패한 수신자는 자동 반복하지 않고 대체 경로를 제안한다.

## 판단 규칙

- `AGENTS.md`의 공식 자료 우선순위와 승인 경계를 따른다.
- 사실과 관찰, 추론, 가치 판단, 제안을 혼합하지 않는다.
- 실행 결과는 `complete`, `partial`, `blocked`, `not_applicable` 중 하나로 기록한다.

## 출력

- `build/outbox/`
- `10-dispatch-manifest.json`
- `dispatches`

## `case.json` 변경 범위

- `dispatches`, 성공 시 `status=dispatched`

선언한 필드 밖의 구조화 상태와 승인 이력은 변경하지 않는다.

## 자체 검증

- 미승인·검증 만료·중복 발송은 차단된다.
- 다른 수신자 주소가 메시지에 없다.
- 배포 고지와 실제 대상이 일치한다.

## 실패·불확실성 처리

- 어댑터 부재 시 초안과 `dispatch-request` 수준에서 멈춘다.
- 공급자 실패를 성공으로 기록하지 않는다.
- 부분 성공은 수신자별 결과로 남긴다.

## 금지 행동

- 승인 없는 발송
- 필터 회피용 문구 변형
- 자동 반복 추적 메일
- 개인 연락처 사용
- 승인 레코드를 스스로 생성하거나 사람을 대신해 승인하지 않는다.
